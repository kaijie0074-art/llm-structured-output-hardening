# 问题报告 RSO-001：LLM 结构化输出漂移导致解析异常与脏数据静默入库

- 编号：RSO-001
- 报告人：杨凯杰（工程师）
- 日期：2026-10-10
- 严重级：P0（付费功能不可用 + 合规风险）
- 状态：已修复（PR #1 合并于 2026-10-13，见 docs/repair-references.md）

## 现象

`POST /api/resume/optimize`（简历字段级改写）：LLM 返回内容不可预测，两类后果交替出现：

1. **用户可见故障**：Jackson `readValue` 抛 `JsonProcessingException` → 接口 500 → 前端提示"优化失败请重试"。客服反馈集中在晚间高峰。
2. **更糟的静默故障**：解析"成功"但内容错误——`field` 指向不存在的经历段、改写文本里凭空出现原文没有的证书/公司/量化数字、"参与"被改写为"主导"。这些结果直接落库并渲染给用户。用户拿含捏造内容的简历去面试被追问，构成**产品级合规风险**（AI 帮学生简历造假）。

## 复现（确定性语料回放）

见 [docs/reproductions/README.md](../reproductions/README.md)。15 个合成语料覆盖六层故障（L1-L6）：

| 层 | 故障 | 语料 |
|---|---|---|
| L1 词法 | ```json 围栏、前后缀寒暄 | 01, 05 |
| L2 语法 | 中文引号定界、单引号、trailing comma | 02, 03, 04 |
| L3 结构 | path 索引越界、必填字段改名、截断 | 06, 07, 14, 15 |
| L4 语义 | score_after 漂移（62→97） | 08 |
| L5 事实 | 捏造证书/公司/量化数字 | 09, 10, 11 |
| L6 回归 | 改 prompt 无评估手段 | eval 黄金集 |

## 基线量化（v0.1.0）

- 15 语料直接 `readValue`：**9/15 崩溃**（用户看到"优化失败"；2026-10-14 口径更正为 7 崩 + 5 静默脏，见 docs/reproductions/README.md）
- 30 份黄金集事后审计：解析"成功"的输出中 **4 份含静默脏数据**（越界/漂移/捏造），无任何告警入库

## 根因

1. 无分层防御：词法/语法层任何偏差直接打到 Jackson 严格解析
2. 无结构校验：schema 只存在于 prompt 里，代码不校验
3. 无事实校验：改写结果与简历原文之间无锚点比对
4. 无回归手段：prompt 每天盲改，效果不可观测（无 eval 集、无 prompt_version 追溯）
