## Q1 六层防御边际贡献分解

**假设**：各防御层贡献不均，存在"空转层"；逐层关闭可量化每层真实贡献。

**实验**（确定性，无 LLM）：`tools/LayerAblation` 对 15 份历史故障语料的 attempt-0
分别以 7 种层配置跑单遍解析（strictOnly / noL1 / noL2 / fullParse / noL3 / noL5 / full），
解析语义与 `ParserChain` 严格一致。

**数据**（evidence/research/q1-layer-ablation.md）：

| 配置 | 解析OK | 静默脏(schema漏) | 最终放行 |
|---|---|---|---|
| strictOnly（无L1/L2） | 8/15 | 0 | 3 |
| noL1（只关围栏剥离） | 11/15 | 0 | 6 |
| noL2（只关语法修复） | 10/15 | 0 | 5 |
| fullParse（L1+L2） | 13/15 | 0 | 8 |
| noL3（关 schema） | 13/15 | **1** | 9 |
| noL5（关锚点） | 13/15 | 0 | **13** |
| full | 13/15 | 0 | 8 |

**边际贡献**：L1 围栏 +2 解析（01 围栏、05 前缀寒暄）；L2 语法修复 +3 解析
（中文引号/尾逗号/单引号键）；L3 schema 拦 1 份静默脏（07 字段改名致 rewritten=null，
若无 L3 将带 null 字段入库）；L5 锚点拦 4 份（路径越界 + 捏造证书/公司/量化）——
关掉 L5 则 13/13 全部放行，**含合规级捏造数据**。无空转层。

**附带发现（缺陷 F1，已修复）**：消融方法学暴露 `Main.baseline` 的语料首段提取缺陷
——`split("===ATTEMPT")[0]` 对"标记开头"语料取到空串，把 06/07 误计为解析崩溃。
修复（`Main.firstAttempt`）后基线口径从"9 崩/4 脏"更正为 **7 崩/5 脏**：
静默脏数据比历史认知多 1 份（06 路径越界、07 null rewritten 实为静默脏而非崩溃），
"解析成功≠数据正确"比旧记录更严重。已加回归测试
（`firstAttempt正确提取标记式语料的首块`、`基线口径修正后崩溃数为7静默脏为5`），
docs/reproductions/README.md 加口径更正注记。

**结论**：六层各有不可替代的贡献；L2 是解析成功率主引擎（+5），L5 是合规生死线
（关掉即全放行）。历史"9 崩"为口径缺陷产物，真实缺陷构成是"崩溃更少、脏数据更多"。

## Q2 对抗性输出损坏穿透测试

**假设**：更恶意的损坏形态（注释注入、全角定界符、零宽字符、NBSP、BOM）可穿透现有 L1/L2。

**实验**（确定性，无 LLM）：`tools/AdversarialProbe` 对同一合法 JSON 施加 12 类损坏，
跑生产 ParserChain，输出穿透矩阵。

**修复前**（/tmp/q2-before.md，6 类穿透）：行内注释、块注释、全角引号、结构位零宽、
NBSP、全角冒号逗号全部 BREACH（解析失败→烧掉一次重试）；另发现 **L1 缺陷 F2**：
全角大括号输出会让 FenceStripper 的跨度起点落到内层 ASCII `{` 上，截出
`{"field":...}`——一个**可解析的静默脏片段**（靠 L3 兜住，defense-in-depth 实证）。

**修复**（`LenientRepair.normalizeStructural`，结构感知归一化 + `FenceStripper` 前置调用）：

- 只在**字符串外部**：剥行内/块注释、删零宽（U+200B/C/D）与 BOM、NBSP→空格、
  全角 ｛｝［］＂：， 映射为 ASCII；
- 字符串**内部**一切字符不碰（值内注释样式文本、中文引号、全角内容是合法内容——内容保真优先）；
- 全角引号定界跟踪开串字符（全角串内的 ASCII `"` 是内容，反之亦然）。

**修复后**（evidence/research/q2-adversarial-matrix.md）：**10 PASS / 3 SCHEMA_OK / 0 BREACH**。
剩余 3 类为**语义损坏**（中文键"章节"、希腊同形字母 ο 键、键内零宽）——词法层不猜语义，
按设计交 L3 拒绝 + 反馈重试，这是刻意的工程边界。新增 6 个回归测试覆盖。

**生产验证（意外收获）**：Q3 的 t00-4 号采样**自然产生**了"中文引号键 + 全角冒号逗号"
损坏（`“score_before”：100`）——正是 Q2 修复所覆盖的形态，修复链当场将其修复成功。

## Q3 同一请求的输出非确定性量化

**假设**：同输入多次采样输出存在漂移，但 temp 降低可收敛。

**实验**（真实 LLM）：同一 resume-001 请求（system+user 逐字节相同），
temp=0.2 采样 8 次、temp=0.0 采样 8 次，全部 200 OK。

**数据**（evidence/research/q3-q4-nondeterminism.md，原始响应 q3-raw/）：

| 指标 | temp=0.0 | temp=0.2 |
|---|---|---|
| 唯一原文变体 | **8/8** | 8/8 |
| 唯一结构签名（field 序列+分数） | 6/8 | 8/8 |
| score_before 值集 | {0,50,70,100} 极差 100 | {0,50,60,70,100} 极差 100 |
| score_after 值集 | {10,70,80,100} 极差 90 | {50,75,80,85,100} 极差 50 |
| sections 覆盖 | 1 段×5 / 2 段×3 | 1 段×2 / 2 段×5 / 3 段×1 |
| fidelity 违规 | 0（文本全忠实） | 0 |
| 自然损坏形态 | 围栏 5/8、中文引号键+全角标点 1/8 | 围栏 7/8 |

**结论**：**同一请求下模型自评分数是无锚噪声**（before 从 0 到 100 都有，after 极差 90）；
sections 覆盖范围（润色几个字段）也不稳定。文本层反而稳定（fidelity 全过）。
围栏违反指令（"不要代码块围栏"）出现 12/16 次——指令遵循在该维度上不可靠但被 L1 兜住。

## Q4 temp=0 与 seed 能否恢复确定性（瓶颈核心证据）

**假设**：非确定性来自采样；温度归零（或固定 seed）应恢复逐位复现。

**实验**（真实 LLM）：temp=0.0 已采 8 次（Q3）；再以 `seed=42` + temp=0 采 4 次
（API 接受该参数，HTTP 200）。

**数据**：temp=0 → **8/8 互异**；temp=0+seed=42 → **4/4 互异**（q3-raw/seed-*.json）。
seed 组内 score_before 跨 {50,80}、after 跨 {70,90}。

**结论**：**该端点的非确定性在服务端**（推断：MoE 路由/批并行内核非确定），temp 与 seed
均无法绕过——应用层（prompt/参数）不存在恢复复现的开关。这是科学复现与 A/B 评估的硬地板。

**复现**（自包含，请求体逐字节固定）：

```bash
# 固定请求体（任意固定 resume JSON + 固定指令，逐字节不变）
cat > req.json <<'J'
{"model":"glm-4-flash","messages":[
 {"role":"system","content":"只输出一个 JSON 对象：{\"sections\":[{\"field\":\"…\",\"original\":\"…\",\"rewritten\":\"…\",\"reason\":\"…\"}],\"score_before\":整数,\"score_after\":整数}"},
 {"role":"user","content":"请优化以下简历：{\"work_exps\":[{\"description\":\"参与订单系统开发，服务 200 家商户\"}]}"}],
 "temperature":0.0, "seed":42}
J
for i in 1 2 3 4; do
  curl -sS https://open.bigmodel.cn/api/coding/paas/v4/chat/completions \
    -H "Authorization: Bearer $LSOH_API_KEY" -H "Content-Type: application/json" \
    -d @req.json | jq -r '.choices[0].message.content' | md5
done   # 预期：4 个互不相同的 md5（本仓实测 8/8、4/4 互异，见下行证据）
# 原始证据：evidence/research/q3-raw/{t00,seed}-*.json（响应体含完整输出与 request_id）
```

## Q5 DRIFT_SUSPECT 阈值调优与误报

**假设**：现行规则（|Δ|>25 或 after≥90）的 after≥90 分支主要被模型自评噪声触发。

**实验**（数据回放，Q3/Q4 的 19 个可解析 benign 采样，同一输入、fidelity 全过）：
扫描 7 种阈值规则（evidence/research/q5-drift-thresholds.md）。

**数据**：benign 输入误报率——现行 47%；Δ-only>25：26%；Δ-only>40：16%；
**Δ-only>50：11%**；after-only≥95：11%。

**落地**（代码+测试）：`OptimizePipeline.maybeFlagDrift` 改为 **|Δ|>50**（去掉 after≥90 分支）：
高分本身无害，跳变幅度才是风险信号；回归测试
`漂移标记只在跳变超过50时触发` + 语料 08 更新为 Δ=57（40→97）代表新口径。
根因层结论：before/after 由模型自评注定不可复现（Q3/Q4），**漂移监控长期应锚定
确定性输入特征**（长度比、量化数字集合差）而非模型自评分数——这是模型能力边界，
非阈值可修。

## Q6 重试反馈模板 A/B 与重试上限

**假设A**：更具体的反馈模板（逐条故障+最小示例）比泛化指令收敛更快。
**假设B**：MAX_LLM_CALLS=2 不足，第 3 次尝试仍有边际收益。

**前置：统计可行性**（双比例检验，α=0.05，功率 80%）——自然失败率 ~3% 场景下
检出 2pp 改善需 **每臂 N=769**（3%→0.5% 也要 431/臂）；10%→5% 仍需 435/臂。
共享订阅配额下不可行 → 自然失败域的 A/B 在经济上就被非确定性锁死。

**实验**（真实 LLM，强制故障协议）：attempt-0 本地注入历史故障形态（围栏+中文引号+
尾逗号），保证首次失败；attempt-1 走生产 `HttpLlmClient` 调真实模型，唯一变量为反馈模板
（A=生产泛化模板 / B=逐条故障+定界规则+最小示例），每臂 8 次。

**数据**（evidence/research/q6-feedback-ab.md）：A 臂 8/8 OK，B 臂 8/8 OK——
**天花板效应**，模板间无可测差异（p50 延迟 ~8s/次，臂间无系统差）。
意外发现：协议前置校验显示 attempt-0 的注入损坏被 **Q2 加固后的修复链当场修复**
（不再消耗重试）——该历史故障类已整体移出重试域。

**结论**：
1. 对 glm-4-flash，反馈模板的具体性不是收敛瓶颈（强制失败域 100% 收敛）；
   自然失败域的模板差异**统计不可测**（需 N≥769/臂）——A/B 优化到此为止是
   测量能力问题，不是工程问题。
2. 重试上限 2 的经验依据：结构类失败一次反馈后 16/16 收敛；截断类（语料 15）
   两次都截断、重试无解（已有回归覆盖）。上限 2 恰好，无证据支持加到 3。

## 瓶颈结论（当前 AI 模型能力的真实上限）

**一句话**：glm-4-flash 在固定输入下的输出非确定性是服务端固有属性
（temp=0：8/8 互异；+seed=42：4/4 互异；自评分数极差 90/100），
使"同一实验逐位复现"与"低失败率场景的 A/B 评估"在应用层不可实现——
Q4（参数无法恢复确定性）、Q5（自评分数为无锚噪声，漂移监控被噪声支配）、
Q6（A/B 需 N≥769/臂）三问连续收敛于此，均为实验证据而非推断。

工程应对（已落地）：确定性防御层吸收**结构**噪声（Q2：0 穿透）；漂移监控改锚定
跳变幅度（Q5：误报 47%→11%）；重试预算 2 次有数据支撑（Q6）；评估指标用
"结构成功率/拦截率"等**对噪声鲁棒**的口径而非逐位复现。
