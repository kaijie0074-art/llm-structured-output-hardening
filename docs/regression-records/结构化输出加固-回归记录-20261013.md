## 评审前实测缺陷（修复过程中真实发现，留档）

| # | 缺陷 | 现象 | 修复 |
|---|---|---|---|
| 1 | schema 校验用未修复文本二次 readTree | 02/04 修复解析成功但树重建失败 → 误判 FAILED | ParseAttempt 携带同源 JsonNode 树 |
| 2 | `allMatch` 对空违规集合返回 true | 干净输出被误判"结构失败"→ 27/30 无谓重试一次 | `!violations.isEmpty() &&` 前置 |
| 3 | 语料块标记语义错位（把 `===ATTEMPT n===` 当块结束） | 双块语料 attempt0 返回空串 → 06/07/14 必 FAILED | 重写为预告式语义 + 单元化 |
| 4 | ResumeSnapshot 未映射 snake_case | work_exps 反序列化为空列表 → 全部 field 判越界 | @JsonProperty 映射 |
| 5 | "3 万"带空格未归一化 | 量化锚点漏抽 | NUMBER 正则容忍空格 |

这五个缺陷全部是**测试与指标先行暴露的**——没有表驱动测试与三指标，它们会以"线上偶发"的形态存活。
